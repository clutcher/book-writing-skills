# decisions.md: the format

`decisions.md` lives in the book (`rules/decisions.md`; its path is `rules.decisions` in
`book.yaml`). It holds every idea about the book that was **discussed and decided, or is still
open**, so that no review raises a decided item again. `decisions.py` in this folder reads,
checks, matches and writes it.

## How a skill reads it

**Read only the index, then open the entries you need.** The file grows long; the index does
not. `decisions.py index` prints one row per entry (id, status, title); `decisions.py show ID`
prints one entry in full; `decisions.py match TEXT` finds the entries a finding may repeat. A
book with no decisions file runs clean: `index` and `match` find nothing and `check` says
SKIPPED.

## Why one file

The same finding comes back in every review, under a new id each time: `R2-4` in one review,
`N.12` in the reading notes, `IC-1` in another run. Nothing joins the ids, so each run finds the
issue again, rates it high, and sometimes proposes as its fix the exact option that was already
rejected. Lists of "rejected, do not re-propose", "locked", "declined" and "settled" items tend to
grow in many places. They all belong here, in one file, with one format.

**What belongs here:** ideas that were discussed, argued or reasoned about. A mechanical fix made
without discussion (a typo, a wrong page number) does not belong here. If an entry's `Why` could
only say "it was wrong", the entry should not exist.

**Dates:** every entry records when its decision was made, because a decision date shows which
ruling replaces which. An entry with no known date says so instead of guessing.

## Statuses

Six statuses in two groups. Every entry has exactly one.

**DECIDED:** the question has an answer. Do not report it again.

- **DECIDED / no change**: considered and declined; the book did not change.
- **DECIDED / changed**: decided and applied to the book.
- **DECIDED / not a finding**: examined and found false, from a misreading of the text.

**OPEN:** the question is live, but it is never a *new* discovery.

- **OPEN / fix owed**: the decision is made; the change never landed, or landed only in part.
  A review that finds one of these again is doing its job.
- **OPEN / decision owed**: discussed, the options exist, the author has not chosen. The entry
  states the exact question.
- **OPEN / undiscussed**: raised by a review, no discussion yet.

## What a review run may do

**Before reporting any finding, match it against this file** (`decisions.py match`), by alias
first and then by keyword, and open each matched entry with `decisions.py show ID`. Matching by id alone always misses, because every review system
has its own ids.

| Status | What a run may do |
|---|---|
| DECIDED (any) | Do not report. To dispute it, cite the entry in one sentence; do not argue it again. |
| OPEN / fix owed | Report as a **regression check**, citing the entry and the fix already agreed. |
| OPEN / decision owed | Report only as a reminder that an answer is owed. Do not argue the options again. |
| OPEN / undiscussed | Report normally, citing the entry so its history travels with the finding. |

`decisions.py policy` prints the same table; code reads it with `run_policy(status)`.

A run that has a finding which is not in the file proposes a new entry (`decisions.py add`, dry
run first) instead of writing it in by hand. The author decides; the run does not.

## File layout

```
# Decisions

Free text: what the file is for. Kept as written, never parsed.

## Index             (generated by decisions.py: never edit it by hand)

| Id | Status | Title |
|---|---|---|
| D-1 | OPEN / undiscussed | Short title of the idea |

## Details           (any `##` heading whose first word is not an id is free text)

## D-1 Short title of the idea

- **Status:** OPEN / undiscussed
- **Aliases:** `L2-3` - `G.14`
- **Idea:** what the finding claims, in the reviewer's words
- **Decision:** what was decided, or the exact question still open
- **Change:** what changed in the book, or the change still owed; left out when nothing changed
- **Why:** the reasons, including every option that was rejected
- **Decided:** 2025-01-31, where it was decided
- **Refs:** files that hold the reasoning
- **Keywords:** words and phrases that help matching
- **Merged:** D-7, D-12

---

## D-2 A short open entry

- **Status:** OPEN / undiscussed
- **Idea:** what the finding claims
- **Decision:** Question: the exact question still open
- **Decided:** None

---

## D-3 ...
```

Rules the parser relies on:

- **Two parts.** `## Index` is generated from the entries: one table row per entry, in file
  order, `| id | status | title |`, with a status the file does not hold shown as `-`.
  `## Details` holds the entries. `decisions.py check --fix` writes the index (and the
  `## Details` heading, before the first entry, when the file has none); `add --fix` and
  `set-status --fix` rebuild it on every write.
- **An entry starts with `## <id> <title>`.** The id is letters, an optional `-`, then numbers
  with optional dots: `D-1`, `D12`, `4.2`. New entries get the next `D-<n>`. These heading forms
  are read as an entry: `## D-1 Title`, `## D-1: Title`, `## D-1. Title`, `## [D-1] Title` and
  `## D-1` (no title). A `##` heading whose first word is not an id is free text and ends the
  entry above it. A `##` heading that starts like an id but is none of these forms is reported
  (`unread-heading`).
- **A field is a bullet line `- **Name:** value`.** `- **Name.** value` is read the same way.
  A value continues on the following lines until a blank line or the next field. Text in an
  entry that is not a field is kept as a note.
- **Field names** are `Status`, `Aliases`, `Idea`, `Decision`, `Change`, `Why`, `Decided`,
  `Refs`, `Keywords`, `Merged`. A longer name that starts with one of them is read as that field
  (`Change owed` is `Change`, `Why it matters` is `Why`). Any other name is reported.
- **Required fields:** `Status`, `Idea`, `Decision` and `Decided` on every entry, and `Why` on
  every DECIDED entry. `Decided` says `None` on an entry that is not decided yet, and says so
  when the date is not known. The other fields (`Aliases`, `Change`, `Keywords`, `Refs`,
  `Merged`, and `Why` on an OPEN entry) are left out when they would be empty: write no
  `None` line for them. A field that is written must have a value. `decisions.py add` writes
  `Decided: None` for an OPEN status and today's date for a DECIDED one, unless `--decided`
  gives a value.
- **Merged** lists the ids of older entries this entry absorbed, comma-separated. Their ids are
  never reused, and the index does not list them.
- **Aliases** are written in backticks, separated by ` - `: `` `R2-4` (readers review 2) -
  `N.12` ``. Text outside the backticks is context and is not matched. A file written before
  aliases were optional may say `none`, which means no alias.
- **Keywords** are comma-separated. A keyword with a space in it is a phrase and scores extra
  when a finding contains it whole.
- **Fenced blocks are never parsed**, so the file can show its own format.

### Status: written, or inferred

The status should be written in the `Status` field. Two older ways are still read, so an
existing file keeps working:

- a `#` section heading that names a status (`# 4. OPEN / fix owed`) gives that status to every
  entry under it;
- a title that ends in ` -- CLOSED: no change`, ` -- RESOLVED` or ` -- SUPERSEDED` gives
  DECIDED / no change, DECIDED / changed and DECIDED / no change.

`decisions.py check` reports every inferred status (`status-not-written`), and
`decisions.py check --fix` writes each one as a `Status` line. After that, an entry can change
status without moving in the file (`decisions.py set-status ID STATUS --fix`).

## Checks

`decisions.py check` follows `check_contract.md`. With no decisions file it says SKIPPED and
exits 0.

| Class | Kind | Meaning |
|---|---|---|
| `no-status` | defect | no Status field and no status section above it |
| `unknown-status` | defect | a status outside the six |
| `duplicate-id` | defect | two entries share an id |
| `missing-field` | defect | a required field is absent (`Why` only on a DECIDED entry) |
| `empty-field` | defect | a field has no value |
| `unknown-field` | defect | a field name outside the list |
| `duplicate-field` | defect | a field written twice in one entry |
| `unread-heading` | defect | a `##` heading that looks like an entry id but is not read as one |
| `index-missing` | defect | no `## Index`; `--fix` builds it |
| `index-stale` | defect | the index does not match the entries; `--fix` rebuilds it |
| `status-not-written` | informational | the status is inferred; `--fix` writes it |
| `fix-owed`, `decision-owed`, `undiscussed` | informational | the open work, so it stays visible |
| `shared-alias` | advisory | one alias on several entries; sometimes right, when an issue was split |
| `undated-decision` | advisory | a DECIDED entry whose Decided field has no date |

## Matching

`decisions.py match TEXT` (or `--text-file FILE`, or text on stdin) lists the entries a finding
may repeat, best first, with the status, a score, what a run may do, and why it matched:

- an **alias** of the entry that appears in the finding is a sure match (score 100 or more);
- otherwise the score is the share of the finding's content words that the entry also holds,
  each word weighted by how rare it is across all entries, and by where it sits in the entry:
  `Keywords` three times, the title twice, `Idea` once. A keyword phrase found whole adds 1.

Scores under `--threshold` (default 0.25) are not shown. A match is a lead for a person or an
agent to read, not a verdict: read the entry before deciding that a finding repeats it.
