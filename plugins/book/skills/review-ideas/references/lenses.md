# Lenses

A lens is one question about the book, owned by one cold reviewer. Lenses are cut so that they
do not overlap: one question, one owner. Two lenses that ask the same question report the same
finding twice; a question no lens owns falls between them and nobody reports it.

`clean-room.py setup` reads this file. Every `### Lens N: Name` section below is one default lens.
The lines `**Question:**` and `**Weight:**` are read by the script, and the rest of the section is
the lens detail that goes into the room's plan. Words in double braces, such as
`{{main_metaphor}}`, are filled from `readers_review` in `book.yaml`. A value the book does not
set is written as "not set: find it in the book", so the lens looks for it itself.

To change the lenses for one book, set `readers_review.lenses` in `book.yaml` (see the end of this
file). Do not edit this file for one book.

## Before any lens reads: the contract

Every lens agent and every skeptic gets the same starting pack, and reads it before the book:

1. **The plan** (`REVIEW-PLAN.md` in the room) and this lens's section of it.
2. **`decisions.md`**, its `## Index` first, then the entries your question touches. Items
   marked DECIDED are not findings. OPEN items are reported only in the
   way the status allows (see `skeptic-rules.md`). **Every lens checks the `OPEN / fix owed`
   entries that fall in its question:** for each one, did the agreed fix reach the manuscript?
   Answer landed, partly landed or not landed, with `file:line`, in the report's
   `## Agreed fixes from earlier rounds` section. This is how the report's continuity table is
   filled; the orchestrator never checks the book itself.
3. **`book/facts.md` and `book/back-cover.md`.** The title, subtitle and cover text live outside
   the manuscript. A lens that did not see them reports "there is no subtitle" or "there is no
   back-cover text" as a blocker. That is a known false finding.
4. **The book's promise**, which the lens writes down in a few lines before reading on:
   - the thesis in one sentence, and the 3 to 5 claims it stands on;
   - the promised audience and what they get (the author names the audience as: {{audience}});
   - what must be true for the book to keep its own promise;
   - what readers of this kind of book expect from it.

The book is judged against its own promise, not against what the reviewer would have written.

A packaging finding (title, subtitle, cover, store page) is damage to sales, not to credibility.
It is never a blocker.

## Voices

Each lens reads through three voices, in this order:

- **The hostile published reviewer**: wants to disagree, hunts for oversimplification and for
  known counterexamples. This is the main voice.
- **The paying reader in the target audience**: is it worth the money and the time? Where would
  they write a bad review, and about what?
- **The comparison**: next to the best books in the field, and the author's earlier work, if
  any, where does this book win and where does it lose?

## The default lenses

### Lens 1: Thesis and argument
**Question:** Does the argument the book stands on hold?
**Weight:** blocker

Name the 3 to 5 claims the book stands on and push on each one. Do two chapters contradict each
other? Do the key definitions stay the same from chapter to chapter? Is any definition circular?
Take the strongest argument against the thesis: does the book answer it or walk around it?
**Can it be wrong:** can something be bad by the book's own definition in a way the book would
admit? **Honest scope:** the book may claim more than its examples show (for example, general
rules drawn from one country, one industry or one group of people). Is the general claim argued, or only stated?

Write findings as **hidden risks, not rebuild plans**: "here is what a hostile reviewer will find;
decide whether to fix it before print."

Run the framing gate in `skeptic-rules.md` before writing any finding of this lens.

### Lens 2: Correctness and evidence
**Question:** Are the claims, the citations and the code true, and do they do what the text says?
**Weight:** blocker

Every factual or research claim: is it supported, and does the text describe the source
correctly? The sources the book's main argument stands on get the closest check:
{{key_sources}}.

**Code: desk-check every code block by careful reading** (never run it). Would it compile? Does
it do what the text says? Does it show the point it is there to show? Keep a numbered coverage
log, one line per code block: OK, or the finding id. If the book has no code, say so in the
coverage log and skip this part.

**The book's own rules:** hold every example to the book's own rules. A hostile reviewer will.

Also:
- **Counting claims:** when the text counts things ("four ingredients", "seven warning signs"),
  check that one counting rule is used every time the same example comes back.
- **Units and arithmetic:** check every calculation, and that each number is in the right unit.
- **List for the source check:** write down every quoted phrase and every one-off figure, with
  its citation, for Stage C to compare against the fetched source.
- **Suspicions you dropped:** write down what you checked and cleared, so a skeptic does not redo
  it.

Claims you can only judge from memory are tagged `recall-based` and sent to Stage C.

### Lens 3: Borrowed research
**Question:** When the book borrows research from another field, is that research described correctly?
**Weight:** blocker

This lens applies only when the book grounds its advice in research from another field (a book on
running that leans on heart studies, a book on saving that leans on behavioural economics). The
field the author names is: {{research_field}}. First decide whether the book borrows from another
field at all. If it does not, say so in one line, write the coverage log, and end the report: the
lens then has no findings and blocks nothing.

- Is each finding described correctly, or does the book claim more than the study showed?
- Does the book move a lab result from one kind of task to its own subject without saying so?
  If the book states once how it moves findings across, judge each later sentence against that
  statement, not against a stricter rule.
- Where the book states a limit once, do the summary, later chapters and tables that repeat the
  claim keep the limit? A reader who skims, and a reviewer who quotes, take away the repeat.
- Verdict for the lens: is "grounded in the research" earned, oversold, or wrong?

Tag each finding with its tier (`skeptic-rules.md`). A claim about a study you did not read is
`recall-based`.

### Lens 4: Teaching
**Question:** Does the book teach the way people actually learn and remember?
**Weight:** major

- Are ideas shown in full worked examples (before and after), or only told?
- Do important ideas come back later and get used again, or are they said once?
- Does any single passage bring in too many new terms at once? If the book's subject is clarity
  or learning, this is also an irony a reviewer will enjoy.
- Does a claim hold for every reader level the book promises? Advice that helps a beginner can
  mislead an expert, and the reverse. The book names its audience as: {{audience}}.
- Is the order right: does any chapter need something that comes later?

Before claiming something is absent ("the book never shows X"), search the whole manuscript for it.

### Lens 5: Mechanics and consistency
**Question:** Are terms, names, citations and cross-references correct and consistent?
**Weight:** major

At print stage this matters more, because every slip is permanent and visible. Terms and their
capitals, code style, citation format, and every "as Chapter N showed": was it really shown there?

**Citations both ways:** every citation key in the text (`[@Key]`, `@Key`) has an entry in
`sources/references.bib`. This part is mechanical: the author ran these checks before the room was made,
and the result is in `review/mechanical-checks.txt` (or the plan says they were not run). This
lens keeps only the parts that need judgment: terms that drift, cross-references that point at the wrong content, and any keys
the scripts could not decide.

Many small slips go in one batched list at the end of the lens report, not one finding each.

### Lens 6: Market and positioning
**Question:** Will the book sell, to whom, and why this book and not the others?
**Weight:** major

- The shelf it belongs on, and the books it will be compared with: {{similar_books}}.
- The one-line difference from those books: is it sharp and early, or buried?
- **Can people find it?** A memorable title may not be searchable; then the subtitle must carry
  the words buyers search for.
- Who buys: readers who buy for themselves, and people who buy for others (a gift, a class, a
  group).
- Signs of credibility, and are they early enough: {{author_background}}.
- The objection "why pay for a book when a free article says the same?": is it answered?

This lens advises on framing, never on truth. Where it conflicts with Lens 1 or 2, they win.

### Lens 7: Reader drop-off and clarity
**Question:** Where does a real reader put the book down?
**Weight:** major

Do chapter openings pull the reader in, and do chapter endings land? Where does the pace drag or
the density jump? Where is a term used before it is explained? This is about readers staying,
not about polishing sentences.

**Skimming:** do the headings alone tell each chapter's story? Can a reader who reads only first
paragraphs still follow the argument? Many buyers judge a book this way in the store preview.

A defect that only shows across the whole book (one rhythm for every chapter, the same opening
move again and again) is a real finding. Count it: how many chapters, how many times.

### Lens 8: Main image
**Question:** Does the book's main image do real work, and does it hold to the last chapter?
**Weight:** major

The main image is the one image, metaphor, running example or named model the whole book is
built around, often the one in the title. For this book it is: {{main_metaphor}}. If it is not
set, name the main image first, in one sentence, and say why you chose it.

- Does it explain, or only decorate?
- Follow it chapter by chapter in a table: introduced, doing work, decorative, absent.
- Does it hold across all chapters, or does it strain and quietly disappear?
- Where the main image borrows facts from another field (physics, biology, sport), are those facts
  right? A slip here is quotable.
- The book's own rules applied to its own main image: if the book asks for precise names, is the
  main image itself precise?

This lens owns the main image. Other lenses leave questions about it to this lens.

### Lens 9: Strengths to protect
**Question:** What is really good in this book and must survive the edits?
**Weight:** strength

An active pass, not a leftover. Reviews lean negative, and every other lens is looking for
faults. Name what is really good, why it works, and what kind of edit would destroy it ("a
tightening pass would cut these lines because they look repeated"). Findings use the severity
`strength`. They skip Stage C and go straight to the report, and they are handed to skeptics as
defence when another lens attacks the same passage.

## Lens report rules (all lenses)

- Read the whole manuscript, start to end, before writing any finding. Whole-book problems only
  show across chapters.
- At most about 12 findings, ranked by priority. Batch small mechanical slips into one list. If
  you have more findings, list the rest one line each (id, severity, location, statement) under
  `## Below the cut`. Nothing is cut silently.
- Answer every `OPEN / fix owed` entry in your area under `## Agreed fixes from earlier rounds`
  (write "none in this lens's area" if there are none).
- One id per finding: `L<lens number>-<n>`, for example `L2-4`. The id never changes afterwards.
- Every finding has a severity, a tier and a location (`file:line` or file and section).
- End with the coverage log: what was fully checked, what was sampled, what was skipped and why.
  A report without a coverage log is not finished.
- Use `templates/lens-report.md`.

## Changing the lenses for one book

In `book.yaml`:

```yaml
readers_review:
  main_metaphor: "the word X in the title, used as a metaphor"
  key_sources: ["@Abc20", "@DE21"]
  research_field: "the psychology of habit"
  similar_books: ["Book One", "Book Two"]
  author_background: "twenty years in the field; named employers"
  lenses:
    - Thesis and argument
    - Correctness and evidence
    - name: Legal risk
      question: Could any passage bring a legal claim?
      weight: major
      detail: Check quotes over fair-use length, named people, trademarks.
```

`lenses` replaces the whole default list. A plain name picks a default lens by its name. A mapping
adds a new lens, or changes a default one when its name matches. Lenses are numbered in the order
listed. Keep the strengths lens: without it the report has nothing to protect.
